Scrum Analytics

Read-only Sprint reports and event timelines for Odoo 19 Community, depending on project_scrum. Metrics come from immutable Sprint scope events, not current task estimates or stage names. Native lists, forms, pivots and graphs supplement ordinary Project reporting.

All point measures use story points rounded to two decimal places. Velocity is completed in-scope points for closed Sprints and is zero before closure. Burndown is unfinished in-scope points; burnup shows completed and total scope. Scope Change shows initial, added, removed and final points. Commitment vs Completion compares original committed points with completed committed points; its ratio uses fractions rather than percentages.

Installation

Follow the repository installation guide.

Configuration

No analytics settings are required. Follow the Scrum setup guide to configure an Agile Project and its Sprints. Sprint setup and lifecycle actions require Administrator under Project in user access rights, called Project administrator below. Project users can read reports for accessible Projects and available companies; reports and timeline points cannot be edited manually.

Usage

The Project > Tasks > Scrum Analytics parent menu currently does not open its report action; this navigation defect is tracked in #53. The Burndown & Burnup Timeline submenu is reachable. The steps below describe the Sprint report when opened, rather than a working parent-menu launch path.

  1. The initial Active Sprints filter shows numbers from the Sprint history so far. Search by Sprint, Project or team, or group by Project, Team, Sprint Status or Sprint End Date.
  2. Remove Active Sprints and select Closed Sprints to review completed Sprints. The current Trusted Closed Replay filter selects closed Sprints with a recorded close time. Their metrics stop there; later task edits do not rewrite them. Do not use a draft report or an older closed Sprint without a close time as a final historical total.
  3. Open a report to compare Original Commitment (Story Points), completed commitment and final scope. Choose Open Sprint for the Sprint form or Open Burndown & Burnup Timeline for its event history.
  4. In the timeline, open a point to see the scope event and values after it; Open Task opens the task when access permits. You can also open Project > Tasks > Scrum Analytics > Burndown & Burnup Timeline and filter by Sprint, Project, task or event type.
  5. Switch to pivot or graph views and select the measures needed. Event timestamps are UTC; date-chart buckets use your Odoo timezone. Timeline values are snapshots after each event, not daily increments: summing them does not give a Sprint total. Use the Sprint report for totals.

As a Project administrator, start and close Sprints through their normal actions. Follow the Scrum completion instructions when recording completed work. If a report seems empty, check filters, Sprint scope history, Project visibility and available companies before comparing metrics.

Bug Tracker

Bugs are tracked on GitHub Issues. In case of trouble, please check there if your issue has already been reported. If you spotted it first, help us to smash it by providing a detailed and welcomed feedback.

Do not contact contributors directly about support or help with technical issues.
