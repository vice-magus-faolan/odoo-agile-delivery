Receive authenticated GitHub webhooks as **Deliveries**, then process
supported events through native Odoo scheduled actions. This optional
Odoo 19 Community addon depends on ``project_agile_git``.

Supported events are ``push``, ``pull_request`` and ``check_run``.
Processing records branches, commits, pull requests, checks and explicit
task-key associations. Receiving and processing GitHub deliveries leave
task completion and stage decisions to your Project workflow and the
separately configured policy addon.

Installation
============

Follow the `repository installation
guide <https://github.com/vice-magus-faolan/odoo-agile-delivery/blob/main/README.md#installation>`__.

Configuration
=============

First configure the repository using the `Git Facts
guide <https://github.com/vice-magus-faolan/odoo-agile-delivery/tree/main/addons/project_agile_git#configuration>`__.
Repository configuration and delivery recovery require **Administrator**
under **Project** in the user access rights, called Project
administrator below. The person setting **Webhook Secret** must also
have System Administrator access. GitHub webhook setup requires
permission to administer that repository webhook.

1. In **Project > Tasks > Git Repositories**, select the repository. Set
   **Provider** to **GitHub**, check **Project** and **Company**, and
   run ``gh api repos/OWNER/REPO --jq .id``. Enter the returned number
   in **Provider Repository Id**. Keep the repository active and set
   **Canonical Url** to its ``https://github.com/`` repository URL.
2. Select **Redacted Excerpt** in **Retention Policy** before sending
   events. **Digest Only** saves delivery metadata but leaves no payload
   for scheduled processing or later reprocessing. Changing the setting
   does not repair earlier deliveries or an exact redelivery of the same
   delivery ID.
3. Set **Webhook Secret** and save. In GitHub, configure the same
   secret, select ``application/json``, and use your externally
   reachable HTTPS Odoo URL followed by
   ``/project_agile_git_github/webhook``. Choose **Let me select
   individual events**, then **Pushes**, **Pull requests** and **Check
   runs**.
4. Odoo.sh runs scheduled actions for you, on a best-effort schedule no
   more often than every five minutes. Self-hosted Odoo needs
   ``max_cron_threads`` above 0. **Normalize Agile GitHub Deliveries**
   is configured every minute, processing at most 20 deliveries per
   invocation. **Purge Expired Agile GitHub Payload Excerpts** is
   configured daily, removing at most 100 expired payloads per
   invocation.

Requests require ``X-GitHub-Event``, ``X-GitHub-Delivery`` and an
exact-body ``X-Hub-Signature-256`` HMAC SHA-256 signature. Bodies larger
than 256 KiB receive HTTP 413 and create no delivery row. A 202 means
Odoo saved the delivery. Check its **State** to see whether it was
processed. An exact duplicate uses the same delivery. A reused delivery
ID with different event type, body digest or size returns HTTP 409.

Redacted Excerpt retains supported fields for facts and task links, not
the full GitHub body. Keys anywhere in complete commit messages and PR
bodies can link tasks; a commit display excerpt is shortened to 255
characters. Excessive keys produce a rejected association decision.
Malformed or oversized required fields produce a **Failed** delivery
with a diagnostic and no retained payload.

Pushes retain the first 100 commits. For larger pushes, **Omitted Commit
Count** and **Commit Omission Reason** identify skipped commits, even
after successful processing or payload cleanup; the branch head still
updates subject to source ordering. See
`ADR-011 <https://github.com/vice-magus-faolan/odoo-agile-delivery/blob/main/docs/adrs/011-git-facts-and-visibility-contract.md>`__
for technical retention bounds.

Redaction removes recognized credentials but may leave sensitive text or
unknown credential formats. Keep such content out of webhook fields and
do not copy payloads or secrets into chatter, tickets or routine
exports. Secret and retained payload access is restricted to System
Administrators.

Usage
=====

Link facts to tasks
-------------------

Use an existing task key such as ``ENG-142`` in one of these supported
source fields:

- ``push``: branch ref and each commit message;
- ``pull_request``: title, body and head branch;
- ``check_run``: name and output title.

For example, use branch ``feature/ENG-142-oauth`` or commit message
``ENG-142: Add OAuth callback``. Keys use an uppercase prefix of 2 to 10
letters or digits starting with a letter, a hyphen, and a positive
decimal suffix. Separate the key from surrounding word characters.
Matching is limited to active tasks in the configured repository Project
and company. Keys are matched throughout complete commit messages and PR
bodies before text is discarded or shortened for display. Other source
text is limited to 4,096 characters. Each source field allows at most 20
distinct keys, each at most 128 characters; more than 20 rejects
associations for that field rather than linking only some keys.

After scheduled processing, open the task and choose **Branches**,
**Commits**, **Pull Requests** or **Checks** to inspect its linked
facts. A missing link can mean the key was unknown, invalid, excessive
or referred to archived work.

Inspect and recover deliveries
------------------------------

Open **Project > Tasks > Git Repositories**, select the repository and
choose **Deliveries**. Inspect **Provider Delivery Id**, **Event Type**,
**State**, **Attempt Count**, **Next Retry At**, **Payload Sha256** and
**Error Summary**. **Replay Mismatch Count** and **Last Replay Mismatch
At** identify conflicting reuse of a delivery ID.

- **Queued** awaits scheduled processing. **Processing** has a
  five-minute lease; an expired lease becomes eligible for another
  claim.
- **Retryable** awaits **Next Retry At**. Transient failures have four
  retry waits of 1, 2, 4 and 8 minutes, totaling 15 minutes. A fifth
  failure becomes **Failed**: about 15 minutes after the first try at
  the configured one-minute scheduler cadence. Correct the cause before
  choosing **Reprocess** for another try. Malformed payloads fail
  without automatic retries; unsupported events with retained payloads
  become **Discarded**.
- **Processed** means processing completed. Inspect task-linked facts to
  see the observations and their source ordering. A push retains at most
  its first 100 commits. **Omitted Commit Count** and **Commit Omission
  Reason** identify any remainder; the branch head still reflects the
  push, subject to source ordering. The notice survives successful
  processing and reprocessing.
- After correcting the cause of a **Failed** or **Discarded** delivery,
  choose **Reprocess** if a retained payload is still available. It
  queues the same delivery again and keeps its attempt count, so a
  delivery that used its five attempts gets one more try.

Authenticated branch-deletion pushes (``deleted: true``, an all-zero
deletion SHA, ``head_commit: null`` and no commits) become **Discarded**
with a branch-deletion reason. They do not create, update or remove
branch, commit, task-link or association-audit facts, and never record
the deletion SHA as a live head. Existing facts, provenance and
source-ordering timestamps remain last observed values, not proof that
the branch still exists on GitHub. A later ordinary push uses the same
source-ordering checks as before; deleting a branch does not reset those
checks. Reprocessing a valid deletion discards it again without changing
facts. Malformed deletion fields and unsafe branch refs remain
**Failed**.

Digest-only, oversized-input and purged deliveries have no payload to
reprocess. After correcting configuration, push again or re-run the
check so GitHub sends a new delivery; for a PR, send a new supported PR
event. Exact redelivery of an old delivery does not fill its missing
payload.

Retained excerpts receive a 30-day expiry. Daily cleanup removes expired
excerpts only from **Processed** or **Discarded** deliveries, in batches
of at most 100. **Retained Payload Purged At** records cleanup; delivery
metadata, digest, facts and association audit remain. **Queued**,
**Processing**, **Retryable** and **Failed** payloads are retained for
recovery even after expiry.

If you spotted it first, help us to smash it by providing a detailed and welcomed
`feedback <https://github.com/vice-magus-faolan/odoo-agile-delivery/issues/new?body=module:%20project_agile_git_github%0Aversion:%20main/addons%0A%0A**Steps%20to%20reproduce**%0A-%20...%0A%0A**Current%20behavior**%0A%0A**Expected%20behavior**>`_.
