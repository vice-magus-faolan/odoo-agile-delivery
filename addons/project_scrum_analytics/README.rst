Read-only Sprint reports and event timelines for Odoo 19 Community,
depending on ``project_scrum``. Metrics come from immutable Sprint scope
events, not current task estimates or stage names. Native lists, forms,
pivots and graphs supplement ordinary Project reporting.

All point measures use story points rounded to two decimal places.
Velocity is completed in-scope points for closed Sprints and is zero
before closure. Burndown is unfinished in-scope points; burnup shows
completed and total scope. Scope Change shows initial, added, removed
and final points. Commitment vs Completion compares original committed
points with completed committed points; its ratio uses fractions rather
than percentages.

Installation
============

Follow the `repository installation
guide <https://github.com/vice-magus-faolan/odoo-agile-delivery/blob/main/README.md#installation>`__.

Configuration
=============

No analytics settings are required. Follow the `Scrum setup
guide <https://github.com/vice-magus-faolan/odoo-agile-delivery/tree/main/addons/project_scrum#configuration>`__
to configure an Agile Project and its Sprints. Sprint setup and
lifecycle actions require **Administrator** under **Project** in user
access rights, called Project administrator below. Project users can
read reports for accessible Projects and available companies; reports
and timeline points cannot be edited manually.

Usage
=====

1. Open **Project > Tasks > Scrum Analytics**. The initial **Active
   Sprints** filter shows live replay. Search by Sprint, Project or
   team, or group by Project, Team, Sprint Status or Sprint End Date.
2. Remove **Active Sprints** and select **Closed Sprints** to review
   completed Sprints. **Trusted Closed Replay** selects closed Sprints
   with a close timestamp. Their metrics stop at that boundary: later
   task edits do not rewrite the closed report. Draft or legacy reports
   without that boundary are not trusted closed replay.
3. Open a report to compare **Original Commitment (Story Points)**,
   completed commitment and final scope. Choose **Open Sprint** for the
   Sprint form or **Open Burndown & Burnup Timeline** for its event
   history.
4. In the timeline, open a point to see the scope event and values after
   it; **Open Task** drills down to the task when access permits. You
   can also open **Project > Tasks > Scrum Analytics > Burndown & Burnup
   Timeline** and filter by Sprint, Project, task or event type.
5. Switch to pivot or graph views and select the measures needed. Event
   timestamps are UTC; date-chart buckets use your Odoo timezone.
   Timeline values are snapshots after each event, not daily increments:
   summing them does not give a Sprint total. Use the Sprint report for
   totals.

As a Project administrator, start and close Sprints through their normal
actions. Actual native Done transitions record **Completed** events; a
stage called Done alone is insufficient. If a report seems empty, check
filters, Sprint scope history, Project visibility and available
companies before comparing metrics.
