Keep the exact requirement context observed at each native Sprint scope
event, separately from current task links. Later specification edits do
not rewrite historical commitment, and Sprint completion does not imply
requirement acceptance.

This optional Odoo 19 Community bridge depends on Agile Solution
Definition (``project_agile_solution``) and Scrum (``project_scrum``).

Installation
============

Follow the `repository installation
guide <https://github.com/vice-magus-faolan/odoo-agile-delivery/blob/main/README.md#installation>`__.

Configuration
=============

Install **Agile Solution Scrum Context**
(``project_agile_solution_scrum``). Follow `Solution
configuration <https://github.com/vice-magus-faolan/odoo-agile-delivery/tree/main/addons/project_agile_solution#configuration>`__
and `Scrum
configuration <https://github.com/vice-magus-faolan/odoo-agile-delivery/tree/main/addons/project_scrum#configuration>`__
for the same Agile Project.

Before linking requirements or starting a Sprint, use a Project
Administrator (Project Manager) account with write access to that
Project and its affected records. Project users can read permitted
Sprint history and exact context; company and referenced-record access
still apply. The bridge requires no separate capture switch and grants
no additional access.

Usage
=====

1. As a Project Manager, use **Project > Deliberate Task Previews** to
   link exact requirement revisions to the Project tasks you plan to
   schedule. Follow the `Solution
   workflow <https://github.com/vice-magus-faolan/odoo-agile-delivery/tree/main/addons/project_agile_solution#usage>`__
   to review and confirm those links.
2. Plan work using **Project > Tasks > Sprints** and the `Scrum
   workflow <https://github.com/vice-magus-faolan/odoo-agile-delivery/tree/main/addons/project_scrum#usage>`__.
   **Start Sprint** records commitment; adding work to an active Sprint
   records added scope. Each new scope event captures the active exact
   requirement links visible at that event, including an optional
   document revision and its observed approval state.
3. Open the Sprint **Scope History** tab. Read **Solution Capture
   Status**: **Exact Context Captured**, **No Active Requirement
   Links**, or **Not Available / Predates Bridge**. Choose the event row
   button **Exact Requirements**, then open a context row to inspect
   **Frozen Observed Content and Approval State**.

Each event keeps its own observed context, including removal,
**Completed**, reopening and carry-over events. A later link to
requirement v2 does not replace v1 on an earlier commitment. Draft
specification context can be captured and is still unapproved;
commitment is neither specification approval nor acceptance. Task Done,
a Completed event and PR merge do not record acceptance: use **Project >
Exact Requirement Decisions** under the Solution acceptance rules.

**No Active Requirement Links** means the event was captured without
links; **Not Available / Predates Bridge** is not proof that historical
work had none. Installation does not backfill old events from current
links. Captured rows are read-only and cannot be recaptured. Losing
access to required references can hide history or prevent capture; it
must not produce apparently complete context. The bridge does not change
Sprint state, assignment, points or analytics formulas.
