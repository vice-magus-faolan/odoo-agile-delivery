Scrum Project Foundation

Scrum Project Foundation (project_scrum) adds Agile teams, Sprints and scope history to Odoo 19 Community Project. It builds on Agile Project Core.

Plan work, start a Sprint, track scope changes and decide where unfinished work goes at closing. One Sprint may be active per Project and team; different teams can have active Sprints in the same Project.

Installation

Follow the repository installation guide.

Configuration

Follow role assignment in Agile core configuration to assign Scrum master before managing teams or Sprints, or combine it with Business analyst for Solution authoring. A Project administrator can also perform Scrum operations. Neither role grants access to a Project or company by itself.

  1. Have a Project administrator configure an Agile-enabled Project using the Agile core configuration.
  2. As a Scrum master, open Project > Tasks > Agile Teams. Create a team and select its Project. The team inherits the Project company.
  3. Have a Project administrator open Project > Configuration > Agile Item Types and review Can Schedule In Sprint. It defaults to enabled. Disable it before scheduling tasks of a type that should stay outside Sprints. A type used by scheduled tasks cannot be made ineligible.
  4. As a Scrum master, open Project > Tasks > Sprints. Create a Sprint with a name, Project and Team, then set Date Start, Date End and Goal. The end date cannot precede the start date. Save in Draft before assigning work.

Project users and Agile members can read permitted teams, Sprints and scope history. They can place their editable tasks through the assignment wizard or Sprint field. Starting and closing Sprints requires Scrum master or Project administrator access, with current access to the affected Project and work.

Usage

Plan a draft Sprint

As a Scrum master or Project administrator, open Project Tasks > Sprints and select the Draft Sprint. Choose Product Backlog to see its Project unscheduled tasks whose Agile Item Type allows Sprint scheduling. Typeless tasks are not eligible. Create and estimate work, then prioritize it with the backlog list handle.

Select tasks from one Project and use Actions > Assign to Sprint. Select the Draft Sprint and choose Apply. The wizard also accepts Active Sprints and records added scope. Alternatively, users with task write access can edit the Sprint field. Tasks can join only a Draft or Active Sprint in their own Project and company.

Set Agile Team on a task to separate BA and development work within one Project. Leave it empty when ownership is not yet known. Assignment gives an unteamed task the Sprint’s team; work already owned by another team is refused. When assigning a selection, either every task moves or none does. Returning work to Product Backlog keeps its team. Filter or group the backlog by Agile Team.

As a Scrum master or Project administrator, choose Sprint Backlog to review assigned work. When the Project uses milestones, this task list shows Milestone and supports native milestone search and grouping. Active Sprint cards show the milestone. Use the milestone’s Release contents to inspect work across Sprints, including completed tasks; a release is not limited to the current Sprint. Select tasks and use Actions > Remove from Sprint, then Apply, to return work to the backlog. Project Tasks > Product Backlog shows all open, unscheduled work, including unschedulable item types and tasks without an item type. The Sprint button and Sprint Planning board show only Sprint-eligible work. Done, Canceled, archived and template tasks stay out of both backlog queues.

Start and work

Open Project Tasks > Active Sprint for current work grouped by stage. Use Agile Team in search to focus on your team. The Active Sprint search filter excludes Draft and Closed Sprints; Sprint Backlog still includes history.

As a Scrum master or Project administrator, choose Start Sprint. Close any Active Sprint for the same Project/team first. Starting freezes all assigned tasks, including archived work, and records Committed events. You need read access to every assigned task; otherwise the Sprint stays Draft without commitment or events. Tasks already in Done state, including archived tasks, also receive Completed events.

To complete a task, set its state to Done. Merely moving it to a stage named Done does not change its state.

In an Active Sprint, membership changes record Added or Removed events; estimate changes record Reestimated with previous and new points. Moving into Done records Completed; moving out records Reopened. Unchanged writes do not add events.

Close and read history

As a Scrum master or Project administrator, choose Close Sprint. When the close wizard opens, choose Move to Product Backlog or Move to Draft Sprint, then Close Sprint. A carry-over target must be a different Draft Sprint for the same Project, company and team. Closing requires edit access to every unfinished task, including archived tasks. Canceled tasks also count as unfinished.

Closing moves all unfinished work or none and records Carried to Product Backlog or Carried to Draft Sprint events. Completed work stays on the closed Sprint. With no unfinished work, closing is direct.

Open Scope History on the Sprint to read immutable events with task, observed points, actor, time and an optional carry-over target column. Closed Sprint assignments are frozen; later task state or estimate changes do not rewrite history. There is no reopen action.

Archive-inclusive starting commitment applies to newly started Sprints. Existing Active and Closed Sprints keep their original commitment and events; earlier gaps for tasks archived before start are not automatically repaired.

Bug Tracker
