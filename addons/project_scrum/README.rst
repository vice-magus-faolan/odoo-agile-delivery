Scrum Project Foundation (``project_scrum``) adds Agile teams, Sprints
and scope history to Odoo 19 Community Project. It builds on `Agile
Project
Core <https://github.com/vice-magus-faolan/odoo-agile-delivery/tree/main/addons/project_agile>`__.

Plan work, start a Sprint, track scope changes and decide where
unfinished work goes at closing. One Sprint may be active per Project
and team; different teams can have active Sprints in the same Project.

Installation
============

Follow the `repository installation
guide <https://github.com/vice-magus-faolan/odoo-agile-delivery/blob/main/README.md#installation>`__.

Configuration
=============

1. Configure an Agile-enabled Project using the `Agile core
   configuration <https://github.com/vice-magus-faolan/odoo-agile-delivery/tree/main/addons/project_agile#configuration>`__.
2. As a Project administrator, open Project **Configuration > Agile
   Teams**. Create a team and select its Project. The team inherits the
   Project company; it does not grant users Project access.
3. Open Project **Configuration > Agile Item Types** and review **Can
   Schedule In Sprint** for each type. It defaults to enabled. Disable
   it before scheduling tasks of a type you want to keep outside
   Sprints; a type in use by scheduled tasks cannot be made ineligible.
4. Open Project **Tasks > Sprints**. Create a Sprint with a name,
   Project and **Team**, then set **Date Start**, **Date End** and
   **Goal**. The end date cannot precede the start date. Save in
   **Draft** before assigning work.

Project users can read teams, Sprints and scope history within their
Project and company access. Project administrators manage teams and
Sprints and use assignment and close wizards. Editing a task Sprint
field uses task write permissions.

Usage
=====

Plan a draft Sprint
-------------------

As a Project administrator, open Project **Tasks > Sprints** and select
the Draft Sprint. Choose **Product Backlog** to see its Project
unscheduled tasks whose **Agile Item Type** allows Sprint scheduling.
Typeless tasks are not eligible. Create and estimate work, then
prioritize it with the backlog list handle.

Select tasks from one Project and use **Actions > Assign to Sprint**.
Select the Draft Sprint and choose **Apply**. The wizard also accepts
Active Sprints and records added scope. Alternatively, users with task
write access can edit the **Sprint** field. Tasks can join only a Draft
or Active Sprint in their own Project and company.

As a Project administrator, choose **Sprint Backlog** to review assigned
work. Select tasks and use **Actions > Remove from Sprint**, then
**Apply**, to return work to the backlog. Project **Tasks > Product
Backlog** is the Agile core backlog, not the Sprint-specific unscheduled
queue.

Start and work
--------------

As a Project administrator, choose **Start Sprint**. Close any Active
Sprint for the same Project/team first. Starting freezes the committed
task set and records **Committed** events. Tasks already in native
**Done** state also receive completion evidence.

In an Active Sprint, membership changes record **Added** or **Removed**
events; estimate changes record **Reestimated** with previous and new
points. Moving into native **Done** (``1_done``) records **Completed**;
moving out records **Reopened**. A stage name alone is not the Done
state. Unchanged writes do not add events.

Close and read history
----------------------

As a Project administrator, choose **Close Sprint**. When the close
wizard opens, choose **Move to Product Backlog** or **Move to Draft
Sprint**, then **Close Sprint**. A carry-over target must be a different
Draft Sprint for the same Project, company and team. Closing requires
edit access to every unfinished task, including archived tasks. Canceled
tasks also count as unfinished.

Closing moves unfinished work atomically and records **Carried to
Product Backlog** or **Carried to Draft Sprint** events. Completed work
stays on the closed Sprint. With no unfinished work, closing is direct.

Open **Scope History** on the Sprint to read immutable events with task,
observed points, actor, time and an optional carry-over target column.
Closed Sprint assignments are frozen; later task state or estimate
changes do not rewrite history. There is no reopen action.
