Agile Project Document Page

Optional Odoo 19 Community bridge designating one OCA Document Page as the documentation root for an Agile Project. It depends on project_agile and OCA document_page_project, which requires document_page and document_knowledge. The bridge and these OCA modules declare AGPL-3 licenses.

Pages retain the native OCA editor, hierarchy, revision history and Project relation. Clearing the root designation does not delete or reparent the page. This is a Project-page bridge, not a Task-page connector or an Enterprise Knowledge integration.

Before public or production use, review the combined deployment’s AGPL-3 corresponding-source obligations as recorded in the adoption decision.

Installation

Follow the repository installation guide.

Configuration

Make the OCA 19.0 document_knowledge, document_page and document_page_project addons available before installing this bridge. Use the selected OCA knowledge commit `e4a12c0c99866a5850840941d6f7ae3b3b27280d <https://github.com/OCA/knowledge/tree/e4a12c0c99866a5850840941d6f7ae3b3b27280d>`__. All three OCA modules and this bridge use AGPL-3. Review the combined deployment’s corresponding-source obligations before use. Run ./scripts/verify-oca-document-page from the repository root to check the selected backend and bridges in disposable databases. The separate check covers installation, update, uninstall and reinstall. Validate your installed extensions and Odoo.sh staging separately. The adoption decision records the selected backend and dependency boundary.

Configure an Agile Project. For this walkthrough, select Administrator under Project in user access rights, called Project administrator below. The caller must also be able to read the selected Document Page; creating a root requires OCA Document Page editor access. Project access alone does not grant page creation. OCA page users can read pages, editors can create and edit them, and managers can delete them, subject to record and company access.

Usage

  1. As a Project administrator with page editor access, open Project > Projects, open the Agile Project form and its Settings tab.
  2. Under Agile Documentation, choose Create Documentation Root. This creates and opens an active content page assigned to this Project and its company. Edit its content with the native Document Page editor.
  3. To designate an existing page instead, select Agile Documentation Root and save. The page must be active content already assigned to the same Project, with either no company or the Project company; categories, archived pages and pages from other Projects are rejected.
  4. Choose the Documentation stat button to return to the page.
  5. To replace the root, choose Clear Documentation Root and confirm, then select or create its replacement. Clearing removes only the designation; the old page, its Project relation and hierarchy remain intact.

If opening fails after a page was archived or changed to a category, restore an appropriate active content page or clear and replace the designation. Actual page deletion is different from clearing: native deletion removes page history and clears the optional root link.
