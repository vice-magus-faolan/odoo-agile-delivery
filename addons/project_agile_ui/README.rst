An optional Sprint Planning workspace for Odoo 19 Community, depending
on ``project_scrum``. It brings draft and active Sprints and eligible
unscheduled work together without replacing ordinary Project or Scrum
list and form views.

The board shows Sprint teams, goals, current points and committed
points, plus work keys, item types, estimates and parent context.
Committed points come from Sprint scope history. See the `Scrum
completion
guide <https://github.com/vice-magus-faolan/odoo-agile-delivery/tree/19.0/addons/project_scrum#start-and-work>`__
for completing work.

Installation
============

Follow the `repository installation
guide <https://github.com/vice-magus-faolan/odoo-agile-delivery/blob/19.0/README.md#installation>`__.

Configuration
=============

Follow the `Scrum setup
guide <https://github.com/vice-magus-faolan/odoo-agile-delivery/tree/19.0/addons/project_scrum#configuration>`__
to enable Agile, create an active team and save a Draft Sprint for the
Project. Setup and Sprint lifecycle actions require **Administrator**
under **Project** in user access rights, called Project administrator
below.

Project users can open the workspace for a visible, active Agile Project
that is not a template. Changing work requires write access to the
affected tasks; creating, starting and closing Sprints still requires a
Project administrator. No separate board configuration is needed.

Usage
=====

1. Open **Project > Projects**, open the Project form and choose
   **Sprint Planning**. The board shows visible Draft and Active Sprints
   with active teams.
2. Find work in the board's **Product Backlog**. This queue includes
   active, unscheduled tasks whose item type permits Sprint scheduling,
   excluding templates. Typeless, Done and Canceled tasks are not
   eligible. Choose **Agile Team** to filter the backlog and Sprints, or
   **All teams** to include unteamed work. Changing teams starts from
   the first page. Use **Load more backlog items** for additional work
   from the same team. Project **Tasks > Product Backlog** is the
   general queue: it also includes unschedulable item types and tasks
   without an item type, which cannot be assigned to a Sprint.
3. Choose a **Draft Sprint**, then **Assign to Sprint**. Alternatively,
   drag the item onto a Draft Sprint. The board does not assign to
   Active Sprints; use the `Scrum
   workflow <https://github.com/vice-magus-faolan/odoo-agile-delivery/tree/19.0/addons/project_scrum#usage>`__
   for the supported native assignment paths.
4. Choose **Return to Product Backlog** on an assigned item to remove it
   from a Draft or Active Sprint. Removal from an Active Sprint records
   scope history. Use **Move earlier** and **Move later**, or drag
   within the backlog, to prioritize work. Buttons provide the same
   actions without dragging.
5. Choose a Sprint name or backlog task key to open its form. **Open
   Sprints list** and **Open Product Backlog list** offer ordinary list
   and form views. The latter keeps the selected team and the board's
   Sprint-eligible queue.

In Sprint Planning, open the native command palette with **Ctrl+K**
(**Command+K** on macOS) and search for **Agile**. Commands create work,
open Product Backlog or Active Sprints, and focus **Find work by key**.
**Keyboard commands** on the board lists the direct shortcuts:
**Alt+Shift+N**, **Alt+Shift+B**, **Alt+Shift+S** and **Alt+Shift+F**,
respectively. On macOS, use Control instead of Alt. Direct shortcuts
require focus on the board and pause while typing, composing text or
using a dialog. Native global shortcuts keep their normal behavior.

Choose **New work item**, enter a **Name** and press **Enter** or
**Create**. The native Task uses the Project default item type,
compatible stage, selected team and milestone. Creation requires current
Task creation permission and an available Agile Project. Before saving,
**Cancel**, **Escape** or the header close button discards the draft
without creating work. While saving, dismissal is unavailable: wait for
the result rather than treating a pending create as canceled. Focus
returns to **New work item** after closing. Saving refreshes the board
without clearing filters; an item whose default type is not
Sprint-eligible may be absent from this planning queue. Use the general
Product Backlog to find it. A rejected save keeps the draft and restores
dismissal: check the Project defaults and current access, or cancel and
refresh to select an available team or milestone.

**Find work by key** searches all visible active work in this Project,
including scheduled items. Type a key or name and select a suggestion or
press **Enter**. The server rechecks the selected item before opening
its native form. **Active Sprint** opens the current Active Sprints
list, narrowed to the selected team; an empty list means no matching
visible Active Sprint.

Use **Next Sprints** to reach Sprints beyond the current 20-Sprint page.
Use **Next assigned items** to reach work beyond the current 100-card
page across those Sprints, including a single Sprint with more than 100
items. Each Sprint shows how many of its visible, filtered items are on
the current page and its complete count. An empty column on one page
does not mean the Sprint is empty. **First Sprints** and **First
assigned items** return to the beginning. The team selector shows up to
100 active teams at a time; choose **Next teams** to reach more, or
**First teams** to start again. The selected team remains available.
These controls replace the current window; backlog paging still adds 50
items at a time. Sprints are ordered by state and descending identity,
teams by identity, and assigned items by backlog sequence then identity.
Assignment inherits a Sprint team only for unteamed work; an
incompatible team selection is refused without moving any work.

For a Project using native milestones, choose **Milestone** to filter
both backlog and Sprint cards. Type a name and select a suggestion or
press Enter. Clearing the field restores all milestones. Changing
milestones restarts backlog paging and keeps the selected team. **Group
loaded items by milestone** groups only the cards already loaded, not
the complete release. Sprint counts and current points use the selected
milestone and caller-visible active assigned work. Commitment points
show committed events for that same currently assigned, visible task
scope; use native Sprint history for the complete historical commitment.
Clear the milestone filter and grouping to reorder work; assignment and
return remain available. **Open Product Backlog list** keeps the
milestone and team. Choose **Release contents** for the selected
milestone's full native task list, grouped by item type and task state,
including completed and scheduled work. Milestone controls and badges
are absent when the Project disables milestones.

After a rejected change, the board refreshes. Review current placement
before retrying. If a page load fails, **Retry** requests that page
again; a changed planning page reloads the first page. If a stale-data
warning appears, reload the page or reopen Sprint Planning before making
another change. If access is denied, check the selected companies and
ask a Project administrator to check your access. The ordinary lists
still require the same permissions.

For task completion, follow `Start and work in the Scrum
guide <https://github.com/vice-magus-faolan/odoo-agile-delivery/tree/19.0/addons/project_scrum#start-and-work>`__.

Active Sprint swimlanes
-----------------------

From the same Project form, choose **Active Sprint board**. Ordinary
**Sprint Planning** and **Active Sprint** lists remain available. Choose
**Epic** or **Assignee** under **Swimlanes**; stages remain columns in
both presentations. **Agile Team** and **Active Sprint** narrow the
work. Type a name and choose a suggestion or press **Enter**; clearing a
selector restores all matching work. Changing the team clears the
selected Sprint.

Epic lanes use the nearest readable item of the seeded Epic type,
including the item itself. Descendants below a Story or Feature remain
under that Epic. Work with no Epic ancestor uses **No Epic**. An
unreadable ancestor, or ancestry beyond 32 levels, uses **Epic context
unavailable** instead of claiming that no Epic exists. Assignee lanes
show one-owner work under that person, work without owners under
**Unassigned**, and work with several owners once under **Multiple
assignees**. Open the native Task to inspect its assignments.

The board shows at most 50 distinct items per page, ordered by identity.
Lane and stage columns describe that window; their counts are page
counts. The **unique visible items** total covers the complete current
filter, not just this page. **Next items** reaches additional cards and
lanes; **Refresh / first items** starts again. **Open lane page** opens
exactly that lane's displayed items. **All filtered work** opens the
complete matching native list. If more than 100 Active Sprints match,
select one Sprint before opening a native work list; the board's item
paging still works across all matching Sprints.

Changing presentation never changes parents or assignees. The board does
not support dragging between stages or lanes. Activate a card with a
click or **Tab**, then **Enter**, to open its native Task form; native
access and per-item-type stage rules still govern edits. Stage columns
appear for the current page's work, not every configured empty stage.
Use the ordinary Project Kanban for its full stage configuration. All
controls are keyboard accessible; the labeled matrix can be focused and
scrolled on narrow screens.

After native edits, refresh the board to see current placement. An
unavailable page clears its cards instead of presenting stale work under
new filters. Use **Refresh / first items** after a changed page, or ask
a Project administrator to check Project, team, Sprint and company
access after a denial.
