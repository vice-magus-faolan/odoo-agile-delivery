Optional Odoo 19 Community bridge linking Sprints to retrospective pages
in OCA Document Page. It depends on ``project_scrum`` and
``document_page_project``; the latter requires ``document_page`` and
``document_knowledge``. The bridge and these OCA modules declare AGPL-3
licenses. Base Scrum remains usable without them.

Retrospectives use native OCA content, editing and page history. The
addon seeds category templates for ADRs, Sprint retrospectives, runbooks
and release notes. It does not provide a Task-page connector or an
Enterprise Knowledge backend.

Installation
============

Follow the `repository installation
guide <https://github.com/vice-magus-faolan/odoo-agile-delivery/blob/main/README.md#installation>`__.

Configuration
=============

Make the OCA 19.0 ``document_knowledge``, ``document_page`` and
``document_page_project`` addons available before installing this
bridge. See the `adoption
decision <https://github.com/vice-magus-faolan/odoo-agile-delivery/blob/main/docs/adrs/006-knowledge-relationship-model.md>`__
for backend selection, then follow the `Scrum setup
guide <https://github.com/vice-magus-faolan/odoo-agile-delivery/tree/main/addons/project_scrum#configuration>`__.

Select **Administrator** under **Project** in user access rights, called
Project administrator below, to manage Sprints and their retrospective
links. OCA Document Page editor access is also needed to create and edit
pages; page read access is required to link or open an existing page.
OCA page managers can delete pages, subject to record and company
access. Project permissions do not grant these page permissions.

Usage
=====

1. As a Project administrator with page editor access, open **Project >
   Tasks > Sprints** and a Draft or Active Sprint.
2. On **Retrospective**, choose **Create Retrospective**. The action
   creates a content page under **Sprint Retrospective Template**,
   copies its template text, assigns the Sprint Project and company, and
   opens the native editor. Fill in the goal, outcome, what went well,
   what did not, actions and owners.
3. Alternatively, select an existing **Retrospective** page and save. It
   must be active content belonging to the same Project and exactly the
   Sprint company.
4. Use the header **Retrospective** button to reopen the page. Before
   closing the Sprint, choose **Clear Retrospective** if you need a
   different link. Clearing neither deletes nor reparents the old page.

Closed Sprints cannot change or clear this link, but the linked page
remains a native editable Document Page for authorized editors; it is
not a frozen copy. If creation reports that the template is unavailable,
have the Document Page administrator check that **Sprint Retrospective
Template** exists, is active and is a category you can read. If opening
fails, check page access, active content status and Project/company
assignment. Deleting the page is not the same as clearing its
designation: native deletion removes its page history.
