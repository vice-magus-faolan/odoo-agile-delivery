Agile Solution Scrum Context

Keep the exact requirement context observed at each native Sprint scope event, separately from current task links. Historical commitment retains the context captured at the time of the event. Record requirement acceptance separately through exact requirement decisions.

This optional Odoo 19 Community bridge depends on Agile Solution Definition (project_agile_solution) and Scrum (project_scrum).

Installation

Follow the repository installation guide.

Configuration

Install Agile Solution Scrum Context (project_agile_solution_scrum). Follow Solution configuration and Scrum configuration for the same Agile Project.

Before linking requirements or starting a Sprint, use a Project administrator account as described in Solution configuration, with write access to that Project and its affected records. Project users can read permitted Sprint history and exact context; company and referenced-record access still apply. Capture starts automatically for new scope events after installation.

Usage

  1. As a Project administrator, use Project > Deliberate Task Previews to link exact requirement revisions to the Project tasks you plan to schedule. Follow the Solution workflow to review and confirm those links.
  2. Plan work using Project > Tasks > Sprints and the Scrum workflow. Start Sprint records commitment; adding work to an active Sprint records added scope. Each new scope event captures the active exact requirement links visible at that event, including an optional document revision and its observed approval state.
  3. Open the Sprint Scope History tab. Read Solution Capture Status: Exact Context Captured, No Active Requirement Links, or Not Available / Predates Bridge. Choose the event row button Exact Requirements, then open a context row to inspect Frozen Observed Content and Approval State.

Each event keeps its own observed context, including removal, Completed, reopening and carry-over events. An earlier commitment retains requirement v1 when a later link selects v2. Draft specification context can be captured and is still unapproved. Approve the specification through the Solution workflow and record acceptance through Project > Exact Requirement Decisions under the Solution acceptance rules.

No Active Requirement Links means the event was captured without links; Not Available / Predates Bridge means there is no bridge record for that event; the work may still have had requirement links at the time. Installation preserves old events as they are. Captured rows are read-only and retain their original snapshot. Losing access to required references can hide history or prevent capture. Continue to manage Sprint state, assignment and points through the native Scrum workflow.
